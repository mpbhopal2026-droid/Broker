SECOND PROBLEM: DOCUMENTS WERE PUBLIC
-------------------------------------
Uploads were made with Cloudinary's default delivery type, which is PUBLIC.
Every KYC document uploaded so far - PAN cards, Aadhaar cards - sits at a
permanent, unauthenticated URL. Anyone with the link has it forever, and no
amount of later configuration takes that back.

Uploads are now created with type=authenticated, and delivery goes through a
signed URL. New documents are protected.

EXISTING DOCUMENTS ARE NOT. To close it:

  Option A (cleanest): ask affected clients to re-upload, then delete the old
  public assets from the Media Library.

  Option B: in the Cloudinary Console, move the existing kyc-documents and
  payment-proofs assets to authenticated delivery, then re-run KYC review to
  confirm the admin viewer still resolves them.

Do not skip this because the URLs look unguessable. They are permanent, they
appear in server logs and browser history, and identity documents at open URLs
is exactly the kind of finding that turns a DPDP complaint into a penalty.


WHY THE FALLBACKS WERE THE REAL BUG
-----------------------------------
A default that keeps the app working when configuration is missing is normally
good practice. A default that is a LIVE CREDENTIAL is the opposite: it removes
the error that would have told you the configuration was missing, and puts the
secret somewhere it will eventually be published. Fail closed instead.
